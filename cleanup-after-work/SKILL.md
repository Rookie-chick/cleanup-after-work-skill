# 收尾清理（Cleanup After Work）

每轮工作结束后，清除本轮产生且不再有用的文件，保持工作区干净。

## 核心原则

只删除同时满足三个条件的文件：**AI 创建的 + 本轮会话产生的 + 明确无用的**。三者缺一，一律保留。

## 预防优于清理：临时文件集中存放

干活过程中，凡一次性用途的文件，一律写入专用临时目录：

- 位置：`{当前工作区}/.workbuddy/tmp/`
- 一次性计算、验证、格式转换脚本：以 `tmp_` 为文件名前缀，放入该目录
- 最终交付物禁止放入该目录

收尾时清空该目录内容即可——目录内文件按定义全部是 AI 产生的临时品。只清空 `tmp/` 的内容，绝不删除 `.workbuddy/` 文件夹本身，也绝不碰其 `memory/`、`skills/` 等兄弟目录。

## 判定清单

### 可删（本轮产生的临时品）

- `.workbuddy/tmp/` 目录下的一切内容
- 散落在其他位置的一次性脚本：`tmp_*`、`verify_*` 等临时计算验证文件
- 已被最终版本取代的中间稿（如 draft 已被 final 替代）
- 跑失败、格式错误的无效输出副本
- 为预览临时下载的副本（用户已有原件）

### 绝不删除

- 用户要求生成或修改的任何文件（报告、PPT、图片、代码等交付物）
- 用户原有的任何文件
- 记忆与人格文件：`.workbuddy/memory/`、`MEMORY.md`、`SOUL.md`、`USER.md`、`IDENTITY.md`
- 项目依赖、配置文件、技能目录
- 拿不准的——一律按此类处理，宁可保留

## 收尾流程

每次完成任务后执行：

1. 回顾本轮的 Write/Bash 操作，列出本轮创建的所有文件
2. 按判定清单分为三类：可删 / 待确认 / 保留
3. 清空 `.workbuddy/tmp/` 内容；删除其他位置明确归属"可删"类的文件
4. 列出"待确认"类文件的路径与判断理由，等待用户明确确认后再删
5. 用一句话汇报清理结果：已删 N 项，待确认 N 项

## 删除方式与红线

- 仅删除 AI 本轮创建的文件；禁止 `rm -rf`、`del /s /q`、通配符批量删除
- 绝不触碰工作区以外的目录（Desktop、Downloads、Documents、用户主目录等）
- 删除失败立即停止并报告，不蛮力重试
- 发现误删立即告知用户，列出路径并说明恢复方式
